## 5. 调用、评价器接口与故障核实

已定位调用链：`shinka_launch` -> `shinka/cli/launch.py` -> `shinka.launch_hydra.main`。评价子进程入口为 `shinka/eval_hydra.py`；配置中的 evaluator 为 `examples.circle_packing.evaluate.main(program_path, results_dir)`。候选入口为 `run_packing`；验证函数为 `adapted_validate_packing`；输出包含 `correct.json`、`metrics.json` 和 `extra.npz`。

核实了三类工程问题：

1. GitHub 网络曾间歇失败，后续克隆与推送成功。并非所有早期失败都有独立结构化记录，不能声称故障归档已完全齐备。
2. Windows GBK 控制台与上游 emoji 日志不兼容；复现说明要求 `PYTHONUTF8=1`。这是日志编码问题，不能自动等同于候选评价失败。
3. 早期 `max_patch_resamples=0` 配置在模型调用前失败，`failure.json` 保留 `proposal_generation_failed`、`api_costs=0`、`generated_code_available=false`。该失败不属于已付费却因输出 token 不足失败的案例。
